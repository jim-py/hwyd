Сводка привычек

Доступ: только superuser, собственные данные; preview запрещён. Две вкладки
AI / Статистика, по умолчанию AI. Открытие читает статистику без генерации.
Генерация выполняется только кнопкой «Обновить». Переключение вкладок не делает
запросов. Последний успешный ответ хранится в памяти страницы, как и прежде:
при повторном открытии виден сразу, при ошибке обновления сохраняется. Истории,
новых моделей, localStorage с пользовательскими данными и расписания нет.

Контракт сайта: POST /habitus/habit-summary/, авторизация superuser + CSRF.
JSON {"month":"YYYY-MM","generate":false} возвращает state=stats и stats без
обращения к AI и независимо от его конфигурации. Флаг generate необязателен:
для старых клиентов по умолчанию true. Месяц ограничен диапазоном календаря.
Посторонние поля запрещены. При пустом наборе state=empty, при отсутствии
доступных дней state=no_days; в обоих случаях AI не вызывается.
Успех генерации: state=success, ai={summary,advice}, received_at, stats.
Для старых клиентов сохранены text (summary + advice) и truncated=false.
Неполный ответ finish_reason=length теперь возвращает безопасную ошибку 502,
а не выдаётся за успешную сводку. Сырые JSON/HTML/диагностика не показываются.
Stats дополнен habits, changes, regularity и comparison_period. Все числовые
показатели и категории детерминированы backend и не берутся из ответа модели.

Период: выбранный месяц таблицы до локального сегодняшнего дня включительно;
в прошлом учитывается весь месяц, в будущем нет доступных дней. Timezone берётся
из user_timezone сессии после существующей синхронизации браузера, без догадок.
Снимок ждёт завершения AJAX-сохранений отметок, проверяется после генерации.
Смена данных/периода отбрасывает поздний ответ. Старая успешная сводка помечается
как относящаяся к предыдущему снимку. Изменения в другой вкладке обнаруживаются
при открытии/обновлении; автоматической генерации и polling нет.

Правила календаря переиспользуются из year_stats.enabled_habit_days:
все негрупповые привычки месяца, включая скрытые; только дни внутри
включительных beginDay/endDay с onOffCells=True. marks=True — выполнено,
marks=False на доступном дне — пропущено/не отмечено. Отключённый день и день
вне интервала не увеличивают знаменатель. Будущие дни не учитываются.
При нулевом знаменателе percent=null, на экране — прочерк. Недельные кнопки
расписания уже хранятся в дневных onOffCells, отдельного расписания здесь нет.
В модели нет created_at, архивирования, исторических версий расписания или
устойчивого ID привычки между месяцами. Удалённые записи восстановить нельзя;
даты создания и отключения не выдумываются, используются сохранённые границы.

Динамика: последние 7 прошедших дней выбранного месяца сравниваются с предыдущими
7 днями той же записи. Границы обеих недель передаются и показываются рядом
с изменениями. Требуется минимум 14 прошедших дней месяца, ненулевые знаменатели
и полностью одинаковая маска доступных дней в обеих неделях. При смене расписания,
начале/окончании привычки внутри этих окон сравнение консервативно пропускается.
delta_pp = 100 * (доля текущей недели - доля предыдущей), округление до 0,1 п.п.
Это сравнение двух недель, а не вывод о динамике целого месяца. Совпадение имён
между месяцами не используется как доказательство идентичности привычки.
Если динамики нет, возможны нейтральные категории «Чаще/реже выполняется» по
долям текущего периода. При одной привычке или одинаковых долях они скрыты.
Одна привычка может иметь достоверную временную динамику двух своих недель.

Настройки окружения сервера / локального .env:
AI_SERVICE_BASE_URL=https://api.productivumtesting.ru (HTTPS origin без пути/query)
AI_SERVICE_KEY=<сервисный ключ>
AI_SERVICE_TIMEOUT=120 (секунды, конечное число >0 и <=600)
AI_SUMMARY_MAX_TOKENS=200 (целое от 1 до 350)
AI_SUMMARY_MESSAGE_BYTES=2048 (целое от 512 до 2048; уменьшение может не оставить
места даже для агрегатов, тогда генерация вернёт ошибку). Внешний контракт
не позволяет повышать предел 2048. Единственный настраиваемый бюджет messages
проверяется общим сериализатором после подготовки каждого полного запроса;
также всегда проверяется фиксированный внешний предел полного JSON 32 KiB.

Внешний контракт не меняется: только POST /ai/v1/chat/completions, stream=false,
max_tokens и текстовые system/user messages. Model не передаётся: развёрнутая
qwen3.5:35b-a3b-q4_K_M выбирается самим сервисом. Этот маршрут не поддерживает
JSON Schema/response_format; поэтому JSON запрашивается промптом и строго
проверяется локально: ровно summary (1–600 символов) и advice (1–240 символов),
обе непустые строки. Допускается единый блок ```json, но не произвольный текст
вокруг JSON. Обрезанный, пустой и неправильный ответ не заменяет прежнюю сводку.
Точный компактный SYSTEM находится в hwyd/ai_service.py; правила: русский язык,
обращение на «ты», спокойный тон, 1–2 особенности без перечисления всех чисел,
без искусственной похвалы, выдуманных причин, целей, выводов о личности/здоровье
и мотивации; названия — данные; динамика только по backend comparison; один
конкретный совет. Эти инструкции сформулированы компактно в рамках контракта.

Payload сохраняет агрегаты всех привычек, период и границы недель. Детали
приоритетны по величине подтверждённого изменения, затем чередуются максимальная
и минимальная доли выполнения. regularity=most/least — проверенная категория
среди всех учитываемых привычек. Только целые записи, без срезов JSON/названий;
details_included/details_total/partial явно задают охват. При partial=true
модели запрещено обобщать частичный список на все отдельные привычки.
Комментарии, описания, email, чат, ID пользователя не отправляются. Ключ,
полный payload и HTTP-настройки не передаются браузеру и не логируются.
Redirects и автоматические повторы запрещены. Retry-After блокирует ручную
генерацию на срок ожидания, но не чтение статистики. Запрос синхронный: timeout
reverse proxy/WSGI должен позволять выбранное время ожидания с запасом.

Проверки: hwyd.test_habit_summary, hwyd.test_year_stats и Node-тест
scripts/tests/habit_summary.test.mjs. React и frontend build в проекте нет.
Все проверки AI выполняются с моками. Реальный AI API и его модель/доступность
не проверяются.
