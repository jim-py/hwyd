Скорость: доступный аналог Lighthouse
-----------------------------------
Команда Lighthouse недоступна. Использованы Edge CDP, Navigation/Resource/Paint
Timing и PerformanceObserver. Это не Lighthouse score и не полевые Core Web Vitals.
Один холодный локальный прогон до/после; телефон 390px, CPU 4x,
1.6 Mbps download / 750 Kbps upload, latency 150ms.

Страница                    LCP до/после       CLS до/после

/home/about/                3512 / 2508ms      0.16547 / 0
/guides/habitus/            новая: 2160ms      0

Мобильная главная: transferSize 633658 -> 405572 байта (примерно -36%).
Изменения текста/страниц также входят в сравнение. При столь малом числе прогонов
это диагностическое наблюдение, не статистическое доказательство и не обещание
скорости для пользователей. На production уже работает gzip HTML/CSS; локальный
runserver измерялся без внешнего OpenResty, поэтому production нужно измерить после
выкладки отдельно. Проверенные сдвиги устранены ранней загрузкой шрифтов и
серверным заполнением автора; ненужный Bootstrap CSS не запрашивается содержательными
страницами. Стиль, шрифты, навигация, формы и трекер сохранены.

Production и оставшиеся действия
-------------------------------
Прямые HTTP-проверки в начале и конце работы сохраняют исходные проблемы:
HTTP / — 200; www — 400; robots/sitemap и новые материалы ещё не выложены (404).
Действующий /home и /home/ — 301 на /; отсутствующая страница остаётся 404.
Поисковый fetch показал устаревшую копию, она не использовалась как актуальный HTTP-аудит.

Выкладка, nginx -t/reload, проверка доверенной proxy/TLS схемы и MySQL не выполнялись.
nginx/OpenResty отсутствуют локально, реальная hosting-конфигурация вне репозитория.
Полный Django suite с известными отсутствующими migration nodes не запускался;
выбраны проверки затронутых контрактов. Существующее диагностическое venv использовано
без повторной полной установки requirements (известная проблема pin gyp остаётся).
